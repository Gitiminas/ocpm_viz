# Decisions

Settled decisions are binding — implement as given. Items marked 🎓 are worth a supervisor
sanity-check but **do not block**. Open questions are listed in §2 and must be resolved before the code that depends on them is written.

Everything here is thesis material: the rationale columns are the raw form of the design chapter.

## 1. Settled

| #   | Decision                                                                                                                                                                                                                                                                                               | Rationale                                                                                                                                                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **No case notion.** The API returns a *sub-log*, described by the query that produced it, not identified by a key. Vocabulary: `objectGraph` / `subLog`.                                                                                                                                               | A `case_id` reintroduces exactly what OCPM discards and undercuts RQ1. The same event may legitimately belong to many sub-logs; a case id forbids that.                                                                                                                                                                    |
| 2   | **Object types closed at five:** `issue`, `pull_request`, `commit`, `actor`, `repo`.                                                                                                                                                                                                                   | Thesis scope is issue → PR → commit plus comments, actors, repo.                                                                                                                                                                                                                                                           |
| 3   | **Multi-object layout:** allocate a sub-lane only when temporal overlap forces it.                                                                                                                                                                                                                     | Sequential objects share a lane; consistency across types is a CD *consistency* requirement.                                                                                                                                                                                                                               |
| 4   | **Lifecycle spans are interval lists**, `intervals: [{start,end},…]`, derived in SQL. One source of truth.                                                                                                                                                                                             | A single `t_start`/`t_end` pair cannot represent a reopened issue.                                                                                                                                                                                                                                                         |
| 5   | **Commit authors and event actors stay separate, labelled identity spaces.** No heuristic email→actor join.                                                                                                                                                                                            | `actor.id` is a GitHub account; `commit_author_name`/`_email` is a git identity string that need not correspond to one. Honesty about provenance is part of the contribution.                                                                                                                                              |
| 6   | **Burst collapse** defaults on above a size threshold; threshold is a UI control, default `> 5` commits.                                                                                                                                                                                               |                                                                                                                                                                                                                                                                                                                            |
| 7   | **Evidence classification: two classes, `validated` and `extracted`.** A link is validated when the platform's own data asserts it — documented GitHub syntax GitHub acts on, or an exact identity match. Extracted when we parsed an unenforced human convention. Mapping in `ADAPTER_AND_API.md` §3. | Nothing in the database pre-classifies links. Stating a *rule* rather than a per-method table makes the classification defensible instead of arbitrary. `inferred` is retired vocabulary. Consequence: branch-name and branch-ref matching become `extracted`, moving most links from solid to dashed — the honest result. |
| 8   | **Statistics are a per-object table, aggregable on demand** — not fixed scalar cards.                                                                                                                                                                                                                  | The existing nine cards assume one issue and one PR.                                                                                                                                                                                                                                                                       |
| 12  | **Metrics are computed in JS over the loaded sub-log**, not precomputed in SQL — durations, counts, gaps. SQL only for figures spanning data not loaded (per-repo link coverage for RQ2).                                                                                                              | Precomputing server-side silently answers "no". Per-object durations are subtraction over timestamps already in memory — SQL adds a round trip and a staleness hazard for nothing. Supersedes the "compute in SQL, not JS" line in `DATA_REQUIREMENTS.md` §9.                                                              |
| 13  | **File format is free; the stack is fixed** (PostgreSQL → PostgREST → D3). Migrating off `.dc.html` to plain HTML + ES modules is permitted and expected.                                                                                                                                              | Software engineering quality is graded and the tool will be maintained by others. The dc-runtime forces remount guards (`window.__ocel*Wired`) and blocks isolated unit testing. Native ES modules need no build step, so this does not reintroduce tooling. `support.js` is then deleted, never edited.                   |
| 14  | **Modularity and tests are graded deliverables**, not polish.                                                                                                                                                                                                                                          | Future students inherit this codebase. Module structure in `ARCHITECTURE.md`.                                                                                                                                                                                                                                              |
| 9   | **All times UTC**, labelled.                                                                                                                                                                                                                                                                           | Current code parses UTC and renders local, so every duration shifts per viewer. Evaluation numbers must reproduce across machines.                                                                                                                                                                                         |
| 10  | **Derived views live in my own schema**, plain `VIEW` by default.                                                                                                                                                                                                                                      | A `mv_thesis_*` prefix in a shared namespace is not isolation. Materialization is a measured optimisation, not a default.                                                                                                                                                                                                  |
| 11  | **Adapter layer rather than waiting for OCEL 2.0 tables.**                                                                                                                                                                                                                                             | The real OCEL tables are parallel PhD work and will not land in time. A thin adapter over the frozen MVs unblocks the visualisation and is a bounded change to replace later. Clean future-work item.                                                                                                                      |
| 15  | **Not every object type gets a lane.** `repo` is a first-class object — searchable, toggleable, a link endpoint, present in object info cards — but it has **no timeline lane**, exactly as `actor` has none. Lanes are for `issue`, `pull_request` and `commit`.                                        | OCPM does not map one-to-one onto GHArchive metadata, and the mockup already embodies this: actors live in the sidebar and in info cards rather than in a lane, and a PushEvent is modelled as a *commit object* rather than an event. A repo has no open/close lifecycle, so a lane would draw a bar encoding nothing. Object-hood and lane-hood are therefore separate properties. Resolves the four-vs-five contradiction between `CLAUDE.md` and decision 2 in favour of five. |
| 16  | **Frontend module structure is the tree in `ARCHITECTURE.md`** — `data/ model/ layout/ render/ state/ stats/`, adopted as proposed. Resolves O8.                                                                                                                                                        | The seam is placed so that everything under `model/`, `layout/` and `stats/` is exercisable without a DOM, which is the stated test of whether the boundaries are right.                                                                                                                                                   |
| 17  | **Test runner is Node's built-in `node --test`** (`npm test`), on a user-local Node 24 LTS. Zero dependencies, zero config, native ES modules.                                                                                                                                                          | Tests are a graded deliverable, and the constraint is no bundler and no build step. Any third-party runner would add a dependency tree and a config file to serve a suite that needs neither. The machine had no JavaScript runtime at all, so one was installed under `~/.local` without `sudo`.                          |
| 18  | **The app is served over http (`npm start`), not opened from disk.** A ~40-line zero-dependency static server lives in `scripts/serve.mjs`.                                                                                                                                                             | An unavoidable consequence of decision 13: browsers block both `<script type="module">` and `fetch()` on `file://` origins, so migrating off the inlined data blob and onto ES modules requires an http origin. No bundler and no build step are involved, and the same server suffices once data comes from PostgREST.    |
| 19  | **Object-hood and lane-hood are separate, and so are node-hood and object-hood.** The commit lane draws one node per commit *object*; the issue and PR lanes draw one node per *event*. Link anchoring must therefore resolve an object to a drawn node only in the commit lane.                        | Discovered as a real defect during Task 1: an object→node map written for every node holds, for a multi-event object, whichever node came last — for the vscode PR, a comment eight days after the merge — which dragged every commit→PR link to the right-hand edge of the chart. Recorded because the asymmetry is easy to reintroduce. |
| 20  | **Detection-method prose is replaced by the enum, not carried alongside it.** Links carry `method`, `link_methods`, `n_methods` and nothing free-text.                                                                                                                                                  | Nothing upstream produces prose; a field only the fixture could populate would make F1 an unfaithful model of a real sub-log. Which specific keyword or SHA matched is recovered properly by the adapter as `link_convention` / `ref_scope`. Consequence: the link tooltip shows `ref_match` rather than a sentence.       |
| 22  | **The sequence spine is drawn per object in the issue and PR lanes**, and per lane only in the commit lane.                                                                                                                                                                                            | With one issue and one PR the two are identical, which is why the mockup could draw it per lane. With two objects in a lane a per-lane spine zigzags between them and asserts a sequence between unrelated PRs that does not exist. Per object it is what it claims to be — that object's own history, traceable across the timeline. The commit lane stays per-lane because each commit is its own object, so per-object would draw nothing. |
| 23  | **Sub-lanes are allocated by greedy interval partitioning over an object's *visual* extent** — its intervals *and* its event times — and touching extents may share a band.                                                                                                                             | Greedy partitioning uses the minimum number of bands, so a band appears only when overlap genuinely forces one (decision 3). The extent includes stray events because an object's footprint is its bar plus its glyphs: the vscode PR merges on 11 March but comments on 19 March, and a second PR sharing that band would interleave with it. Touching extents share a band because the span does not overlap; the collision loop separates the two glyphs at that instant. |
| 21  | **Highlights-mode ticks mark lifecycle interval boundaries**, not the last of an object's terminal events.                                                                                                                                                                                             | Generalizes to N objects and to reopens, and stays consistent with the lifecycle bar that is actually drawn. ⚠️ Visible consequence on F1: the PR closes two seconds after it merges, so the mockup ticked `22:47:51` (closed) where this ticks `22:47:49` (merged). Flagged for review — see the Task 1 report.           |
